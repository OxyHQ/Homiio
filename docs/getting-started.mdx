# Getting started

Homiio is a Bun workspaces monorepo with three packages: `@homiio/frontend` (Expo / React Native), `@homiio/backend` (Express + drizzle / PostgreSQL), and `@homiio/shared-types` (pure TypeScript). This guide takes you from a clean checkout to a running dev environment.

## Prerequisites

- **Node.js 22.x** — pinned in the root `engines` field. Use `nvm` / `fnm` / `mise` to switch.
- **Bun 1.0+** — the only supported package manager. `npm` and `yarn` are not maintained.
- **PostgreSQL with PostGIS** — start one with `docker compose -f docker-compose.postgres.yml up -d postgres` (it pins `postgis/postgis:17-3.5`, the same image CI uses).
- **iOS development**: macOS + Xcode 16 with the iOS 17 simulator.
- **Android development**: Android Studio with at least one configured AVD.
- **Web only**: nothing extra — `bun run dev:frontend` then press `w`.

Optional but recommended: Stripe CLI (for webhook forwarding in dev). Photos and private documents are stored in Oxy Files, through the Oxy service identity below; there is no bucket to configure. Sindi and Alia need nothing from the backend: the app talks to Alia through `@alia.onl/sdk` under the signed-in person's Oxy session, so they work against a local backend as they do in production.

## Clone and install

```sh
git clone https://github.com/OxyHQ/Homiio.git
cd Homiio
bun install
```

`bun install` resolves every workspace, then runs `bun run build:shared-types` as `postinstall`. The compiled backend resolves `@homiio/shared-types` through that `dist`, so the postinstall step is load-bearing for it — do not skip it. The frontend never reads it: Metro, `tsc` and Jest all take the package from `packages/shared-types/src` through `tsconfig.json`'s `paths`.

## Configure environment

Two env files, one per backed service.

`packages/backend/.env`:

```env
DATABASE_URL=postgres://homiio:homiio@127.0.0.1:5434/homiio_dev
OXY_API_URL=https://api.oxy.so
PORT=4000
NODE_ENV=development

# Stripe (optional in dev — endpoints return 501 STRIPE_NOT_CONFIGURED if unset)
STRIPE_SECRET_KEY=sk_test_...
STRIPE_WEBHOOK_SECRET=whsec_...
STRIPE_PRICE_PLUS=price_...
STRIPE_PRICE_FILE=price_...
STRIPE_SUCCESS_URL=http://localhost:8130/success
STRIPE_CANCEL_URL=http://localhost:8130/profile/subscriptions

# Homiio's Oxy service identity (the capability catalogue, reviews, evictions).
# A product-to-Oxy credential, never an upstream provider key. The pair is
# LOCAL ONLY: a deployed Homiio attests its ECS task role instead (oxy ADR 0026)
# and carries neither variable.
OXY_SERVICE_API_KEY=oxy_dk_...
OXY_SERVICE_API_SECRET=...
```

`packages/frontend/.env`:

```env
EXPO_PUBLIC_OXY_BASE_URL=https://api.oxy.so
API_URL=http://localhost:4130

# Optional Stripe Payment Link fallbacks for when Checkout API is unavailable
EXPO_PUBLIC_STRIPE_LINK_PLUS=https://buy.stripe.com/...
EXPO_PUBLIC_STRIPE_LINK_FILE=https://buy.stripe.com/...
```

`EXPO_PUBLIC_OXY_BASE_URL` defaults to the Oxy production API (`https://api.oxy.so`) in every environment — there is no dev fallback. Override it only when you are genuinely running an Oxy API yourself.

## Run the dev servers

```sh
# Start frontend and backend in parallel
bun run dev

# Or run them in separate terminals
bun run dev:backend     # nodemon + ts-node, http://localhost:4130
bun run dev:frontend    # Expo with --tunnel, opens the dev menu
```

Inside the Expo CLI:

- Press `w` for the web preview.
- Press `i` for the iOS simulator.
- Press `a` for the Android emulator.
- Press `r` to reload, `j` to open the JS debugger.

The backend exposes `GET /health` (unauthenticated) — hit it from a second terminal to confirm PostgreSQL is connected:

```sh
curl http://localhost:4130/health | jq
```

If `database.status` is anything other than `"connected"`, check the `DATABASE_URL` value and that Postgres is running (`docker compose -f docker-compose.postgres.yml up -d postgres`).

## Build for production

```sh
bun run build           # All packages
bun run build:frontend  # Expo web export -> packages/frontend/dist
bun run build:backend   # tsc -> packages/backend/dist
```

The frontend web export is what the Cloudflare Worker serves. The backend is deployed separately to AWS ECS — see [Deployment](./deployment).

## Useful scripts

```sh
bun run test            # Run tests across all packages
bun run lint            # Biome + the frontend's minimal ESLint
bun run format          # Format with Biome
bun run clean           # Remove dist directories and node_modules
```

For backend-only diagnostics (Stripe wiring, subscription state, image upload smoke test) check `packages/backend/scripts/` — every script is invoked via `ts-node --transpile-only`.
